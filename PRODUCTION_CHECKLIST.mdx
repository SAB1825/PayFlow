## 🔴 Money Correctness — *do these before any real funds move*

- [ ] **Persist the idempotency key** — `toPersistance()` in `transfer.repository.ts` omits `idempotencyKey`, so the unique constraint never fires and every retry double-debits.
- [ ] **Make transfer + balances atomic** — `create()` and `markSuccess()` currently commit outside the balance transaction; a crash in between leaves money in limbo.
- [ ] **Handle duplicate keys without aborting the tx** — use `INSERT ... ON CONFLICT DO NOTHING RETURNING` instead of catching a violation.
- [ ] **Add database `CHECK` constraints** — `balance >= 0`, `amount > 0`, `from_acc_id <> to_acc_id`, and currency matching.

## 🟠 Security & Auth — *before facing untrusted traffic*

- [ ] **Fix the 400-instead-of-401** — `auth.gaurd.ts` throws `ApplicationException` with no code, so invalid tokens return `BAD_REQUEST`.
- [ ] **Pin the JWT algorithm** — pass `algorithms: ['HS256']` in both the guard and `TokenService`; add `issuer` and `audience`.
- [ ] **Add rate limiting** — `@nestjs/throttler` on `/auth/login`, `/auth/register`, and `/transfer`.
- [ ] **Swap argon2 → SHA-256 for refresh tokens** — argon2 costs ~100ms CPU on a public endpoint and is a DoS vector. Keep argon2 for passwords only.
- [ ] **Add a logout endpoint** — revoke the refresh token and clear the cookie.
- [ ] **Make the guard run once** — it is registered as `APP_GUARD` *and* via `@UseGuards` on every controller; drop the duplicates.
- [ ] **Fix the beneficiary unique constraint** — `acount_number` is globally unique, so only one user can ever add a given account. Scope it to `owner_user_id`.
- [ ] **Support multiple sessions with token families** — today one login kills all others, and replaying an old token revokes the legitimate session.
- [ ] **Settle the refresh-token transport** — login sets an httpOnly cookie but `/auth/refresh` reads the body. Pick one and add CSRF protection if you keep cookies.

## 🟡 Scale & Performance

- [ ] **Index the transfer hot path** — add `(from_acc_id, created_at desc)` and `(to_acc_id, created_at desc)`; `findByAccountId` currently seq-scans the fastest-growing table.
- [ ] **Paginate list endpoints** — `findByAccountId` accepts `limit`/`offset` but the handler never passes them.
- [ ] **Configure the connection pool** — set `max`, `idleTimeoutMillis`, `connectionTimeoutMillis`, `statement_timeout`, and TLS; close the pool on shutdown.
- [ ] **Tighten money input** — switch `amount` to a string decimal parsed with integer math, and add `@IsInt` / `@Min` / `@Max`.

## ⚪ Ops & Delivery

- [ ] **Add structured logging** — there is currently zero `Logger` usage. Include a correlation id, and never log tokens or PII.
- [ ] **Add health checks** — `/health/live` and `/health/ready` (the latter verifies Postgres).
- [ ] **Add a catch-all exception filter** — unexpected errors currently escape as HTML with a stack trace.
- [ ] **Enable graceful shutdown** — `app.enableShutdownHooks()` plus pool draining so deploys do not kill in-flight transfers.
- [ ] **Fix the e2e suite** — `app.e2e-spec.ts` asserts a `/` route that no longer exists; it is failing or was never run.
- [ ] **Add unit tests for money** — cover `Money`, `withdraw`/`deposit`, concurrent transfers, insufficient funds under lock, and idempotent replay.
- [ ] **Add CI** — run typecheck, lint, tests, and `drizzle-kit check` on every PR.
- [ ] **Add a Dockerfile** — multi-stage, non-root, `NODE_ENV=production`, exec form so signals reach Node.

## 🧭 Longer Term

- [ ] **Introduce an append-only double-entry ledger** — every transfer writes a debit and a credit that must sum to zero; balances become a rebuildable projection.
- [ ] **Wire up KurrentDB** — `DomainEvent` and the event store are already in place but unused; a good home for the audit trail.
- [ ] **Add a stuck-transfer reconciler** — sweep `PENDING` rows older than a threshold and alert.
- [ ] **Validate env at boot** — fail fast with a config schema instead of `getOrThrow` failing mid-request.
- [ ] **Rewrite the README** — document the paise-as-integer decision, migrations, and the operational runbook.
